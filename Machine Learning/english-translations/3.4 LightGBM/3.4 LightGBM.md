## 1. What is LightGBM

Microsoft’s DMTK (Distributed Machine Learning Toolkit) team open-sourced LightGBM on GitHub. It quickly gained popularity for outperforming other boosting tools. On the Higgs dataset, LightGBM is about 10× faster than XGBoost, uses roughly 1/6 the memory, and achieves better accuracy.

GBDT typically traverses the full training data multiple times per iteration. Loading all data into memory limits scale; disk I/O is slow. For industrial-scale data, plain GBDT is often insufficient. LightGBM was designed to make GBDT practical on massive data.

### 1.1 Where Does LightGBM Optimize (vs. XGBoost)?

- Histogram-based decision tree algorithm
- Leaf-wise growth with depth limit
- Histogram difference acceleration
- Native support for categorical features
- Cache hit optimization
- Histogram-based sparse feature optimization
- Multi-threading

### 1.2 Histogram Algorithm

The histogram algorithm discretizes continuous features into k bins (e.g., [0,0.1)→0, [0.1,0.3)→1). While scanning data, it accumulates statistics in a histogram of k bins. After one pass, it searches over bin boundaries for the best split.

**Benefits**: Lower memory (no pre-sorted indices; 8-bit bin indices suffice—about 1/8 the memory). Fewer split evaluations: pre-sorting requires O(#data × #features) split checks; histogram needs only O(k × #features) with k as constant.

### 1.3 Leaf-wise Growth with Depth Limit

XGBoost uses **level-wise** growth: all nodes at the same level are split, then pruning. Level-wise is easy to parallelize and controls complexity but is inefficient: it splits all leaves equally even when many have low gain.

LightGBM uses **leaf-wise** growth with a depth limit: at each step, pick the leaf with the largest gain and split it. For the same number of splits, leaf-wise reduces error more than level-wise. The downside is deeper trees and overfitting risk, so LightGBM adds a max depth limit.

### 1.4 Histogram Difference Acceleration

A leaf’s histogram can be obtained by subtracting its sibling’s histogram from the parent’s. Building a histogram normally requires scanning all data in the leaf; with histogram differencing we only traverse k bins. This can roughly double speed for building sibling histograms.

### 1.5 Native Support for Categorical Features

Most ML tools cannot handle categorical features directly; they require one-hot or similar encoding, which is space- and time-consuming. LightGBM supports categorical features natively, without extra encoding, and adds split rules for them. On the Expo dataset, this gave ~8× speedup with the same accuracy. LightGBM is among the first GBDT tools to support categorical features directly.

## 2. LightGBM Advantages

LightGBM is a GBDT framework with efficient parallel training and:

- Faster training
- Lower memory usage
- Better accuracy
- Distributed support for large-scale data
