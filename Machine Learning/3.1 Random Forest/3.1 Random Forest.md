## 1. What is Random Forest

### 1.1 Bagging Idea

Bagging stands for bootstrap aggregating. The idea: randomly sample a subset of the total data for training, repeat many times, and aggregate results (e.g., by voting or averaging). This reduces the impact of bad/noisy samples and improves accuracy.

**Example**: 1000 samples. Instead of training on all 1000, sample 800 for training. If noise points are outside the 800, they are effectively excluded. Repeat and average to improve robustness.

### 1.2 Random Forest

Random Forest is a tree-based variant of Bagging. One tree alone is weak; many trees together improve generalization (akin to "three cobblers equal one wise strategist"—many weak learners can outperform one strong one).

With the same data and algorithm, we would normally get only one tree. Bagging helps: with replacement sampling we obtain different bootstrap sets and train different classifiers. Repeat m times to get m classifiers; the final decision is by majority vote.

**Each tree is built as follows:**

1. Sample N training samples with replacement from the training set (size N) for this tree.
2. If each sample has M features, choose a constant m << M and randomly select m features. At each split, choose the best split among these m features.
3. Each tree grows to full depth without pruning.

The two sources of randomness (sample and feature) are crucial for avoiding overfitting and improving robustness (e.g., to missing values).

In short: random samples, random features, random classifier type; build multiple decision trees and vote (**voting mechanisms**: one-veto, majority, weighted majority).

## 2. Factors Affecting Random Forest Classification Performance

- **Correlation between trees**: Higher correlation → higher error rate.
- **Individual tree strength**: Stronger trees → lower overall error rate.

Decreasing m (feature subset size) reduces both correlation and strength; increasing m raises both. The key is choosing the optimal m (or range)—this is the main hyperparameter in Random Forest.

## 3. Pros and Cons of Random Forest

**Pros:**

- Often performs well on many datasets.
- Handles high-dimensional data without explicit feature selection (features are randomly sampled).
- Can output feature importance after training.
- Fast to train; easy to parallelize (trees are independent).
- Can capture feature interactions during training.
- Can balance error for imbalanced datasets.
- Tolerates many missing features while maintaining accuracy.

**Cons:**

- Can overfit on noisy classification or regression problems.
- For features with many values, attributes with more values tend to dominate; attribute importances may be unreliable.

## 4. How Does Random Forest Handle Missing Values?

Given its training procedure, Random Forest handles missing values in a special way:

1. **Impute initial values**: For numerical features, use median or mode of non-missing data.
2. **Build a forest** with imputed values and run all data through it. Record the path (sequence of splits) for each sample.
3. **Similarity matrix**: Find samples whose paths are most similar to the missing-data sample.
4. **Update imputation**: For categorical variables, use weighted voting; for numerical, use weighted average. Iterate until imputed values stabilize.

This is analogous to collaborative filtering in recommendation: estimate missing values from similar samples. The path-based similarity is what makes Random Forest's approach unique.

## 5. What is OOB? How is OOB Computed in Random Forest?

**OOB (Out-of-Bag)**:

In bagging, about 1/3 of samples do not appear in each bootstrap sample and thus do not participate in building that tree. These are **out-of-bag (OOB) samples**. They can replace a separate test set for error estimation.

**OOB error computation:**

- For the trained forest, use OOB samples as the test set. Suppose there are O OOB samples.
- Run them through the forest and get O predictions.
- Compare with true labels; let X be the number of errors. OOB error = X/O.

**Pros and cons:**

OOB error is an unbiased estimate. So for Random Forest, cross-validation or a separate test set is not strictly needed for unbiased error estimation.

## 6. Overfitting in Random Forest

You built a Random Forest with 10000 trees. Training error is 0.00, but validation error is 34.23. What's going on? The model is overfitting. Use cross-validation to tune the number of trees.
